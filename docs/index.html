PATCHRIPPLE / OPEN SOURCE

See what a pull request may affect.

A deterministic CLI and GitHub Action that map changed files, static import dependents, related tests, and repository owners. Keep the offline output or publish it yourself.

Static candidates are possibilities, not runtime effects, coverage, or change-safety proof. Incomplete analysis remains visibly incomplete.

Install merged main

Use Node.js 24 or newer and npm. The main source pin is immutable and installs from an HTTPS archive without a Git clone:

npm install --global --ignore-scripts --no-audit --no-fund "https://github.com/icecold009/PatchRipple/archive/4b45616e941ebe349b845a62a8941c586fbb18c5.tar.gz"
patchripple --version

This evidence snapshot has no versioned GitHub release or tag, and the public npm registry has no patchripple package.

Fetch and analyze a pull request

For a public GitHub PR, fetch its base branch and head into fixed PatchRipple refs. This downloads Git objects but does not check out or run target code; it leaves the target branch and working tree unchanged. Local URL rewrites cause the command to stop.

patchripple fetch-pr --repo /path/to/target --repository owner/repo --base-branch main --pr 123
patchripple doctor --repo /path/to/target --base refs/patchripple/manual/base --head refs/patchripple/manual/head --out /path/to/new-bundle
patchripple analyze --repo /path/to/target --base refs/patchripple/manual/base --head refs/patchripple/manual/head --repository https://github.com/owner/repo --out /path/to/new-bundle

The read-only doctor checks Node, Git history, exact revisions, and whether the output location is new and outside the target. PR mode compares the merge-base of the base tip and head. Use --mode direct for an explicit two-commit comparison. In shallow clones, fetch enough history for Git to find the merge base.

Open index.html from the generated bundle. It contains all required assets and data; there are no external requests. The bundle also includes graph JSON, SVG, and run metadata. The list and graph expose exact revision attribution.

Use the read-only consumer workflow template, pinned to the full commit 4b45616e941ebe349b845a62a8941c586fbb18c5. This is an immutable pre-release pin, not a versioned release. Keep pull_request, contents: read, and persist-credentials: false. The trusted Action ships with its parser assets; it never installs dependencies or executes scripts from the target PR.

Coverage and limits

  • JavaScript/TypeScript literal imports, re-exports, type imports, dynamic literal imports, require, nested tsconfig with bounded in-repository relative extends, and package exports from npm/Yarn/pnpm workspaces. Workspace declarations support simple top-level package lists and multiple flat brace groups with 2–16 alternatives each, capped at 256 expansions; nested groups, character classes, advanced YAML, external config inheritance, and TypeScript project-reference build semantics remain unsupported. Non-empty project references are marked incomplete.
  • Python static import/from, explicit and common monorepo src roots, relative packages, and existing initializers. Dynamic imports, wildcard symbol relationships, namespace ambiguity, and unsupported syntax are warnings.
  • Base/head import graphs contribute impact; removed and renamed paths keep their revision provenance. CODEOWNERS metadata comes from the base branch tip.
  • Tests are related by imports and documented naming conventions. A related test is not coverage proof.
  • Hard defaults: 5,000 files and 40 MiB per revision, 512 KiB per file, 500 candidates, 2,000 displayed edges, depth 20, and a 60-second Git/parsing deadline. Limits can be reduced.

Expected external package exclusions remain visible without alone making the graph incomplete. Unresolved local imports, unsupported configuration, parser uncertainty, and truncation are separately classified and mark the graph incomplete. Exit 0 means valid output, not necessarily complete analysis.

Trust, data and sharing

No target code, build scripts, executable config, hooks, project installs, database, account, or hosted analyzer is involved. Untrusted source is read as bounded inert Git blobs; output is escaped and the interactive viewer uses a hashed Content Security Policy.

Output reveals repository paths, ownership, and relationships. GitHub artifact downloads require sign-in/read access and expire according to retention settings. For an anonymous permanent URL, the repository owner publishes the static bundle separately to a host they control. Hosting terms must be checked before making a free-tier promise.

No PR comments, branch writes, deployments, or package publication happen automatically. Never use pull_request_target, secrets or write permissions for untrusted analysis.
