PATCHRIPPLE / OPEN SOURCE

See what a pull request may affect.

A deterministic CLI and GitHub Action that map changed files, static import dependents, related tests, and repository owners. Keep the offline output or publish it yourself.

Static candidates are possibilities, not runtime effects, coverage, or change-safety proof. Incomplete analysis remains visibly incomplete.

Run locally

Node 24 and Git are required. Build from the trusted PatchRipple checkout, not from the repository you are analyzing.

npm ci --ignore-scripts
npm run verify
node dist/cli.cjs analyze \
  --repo /path/to/target \
  --base BASE_COMMIT --head HEAD_COMMIT \
  --repository https://github.com/owner/repo \
  --out /path/to/new-bundle

PR mode compares the merge-base of the base tip and head to head. Use --mode direct only when you want an explicit two-commit comparison. Fetch missing commit history before analysis. The output directory must be new and outside the analyzed repository.

Open index.html from the generated bundle. It contains all required assets and data; there are no external requests. The bundle also includes graph JSON, SVG, and run metadata. The list and graph expose exact revision attribution.

Install the Action

Use the read-only consumer workflow template. Replace PATCHRIPPLE_COMMIT with a reviewed published immutable commit. The placeholder is intentionally not executable installation guidance until a trusted Action commit has been published.

Fetch and verify exact base/head objects, including the base repository's PR ref for a fork. Use pull_request, contents: read, and persist-credentials: false. The trusted Action ships with its parser assets; it never installs dependencies or executes scripts from the target PR.

Coverage and limits

  • JavaScript/TypeScript literal imports, re-exports, type imports, dynamic literal imports, require, relative resolution, and bounded root tsconfig paths/baseUrl.
  • Python static import/from, explicit source roots, relative packages, and existing initializers. Dynamic imports, wildcard symbol relationships, namespace ambiguity, and unsupported syntax are warnings.
  • Base/head import graphs contribute impact; removed and renamed paths keep their revision provenance. CODEOWNERS metadata comes from the base branch tip.
  • Tests are related by imports and documented naming conventions. A related test is not coverage proof.
  • Hard defaults: 5,000 files and 40 MiB per revision, 512 KiB per file, 500 candidates, 2,000 displayed edges, depth 20, and a 60-second Git/parsing deadline. Limits can be reduced.

Package/workspace imports, config extends, unsupported languages, symlinks/submodules, binary or non-UTF8 input, unresolved relationships, and truncation warn. Any warning or omission marks analysis incomplete. Exit 0 means valid output, not necessarily complete analysis.

Trust, data and sharing

No target code, build scripts, executable config, hooks, project installs, database, account, or hosted analyzer is involved. Untrusted source is read as bounded inert Git blobs; output is escaped and the interactive viewer uses a hashed Content Security Policy.

Output reveals repository paths, ownership, and relationships. GitHub artifact downloads require sign-in/read access and expire according to retention settings. For an anonymous permanent URL, the repository owner publishes the static bundle separately to a host they control. Hosting terms must be checked before making a free-tier promise.

No PR comments, branch writes, deployments, or package publication happen automatically. Never use pull_request_target, secrets or write permissions for untrusted analysis.

Verification status

The synthetic demo illustrates the viewer; its example SHAs are not public source revisions. Local parser/Git regressions, isolated packaging and offline desktop/mobile browser checks pass. Actual same-repository/fork Action runs and maintainer trials remain release evidence requirements.
